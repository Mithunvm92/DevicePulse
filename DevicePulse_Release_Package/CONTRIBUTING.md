# Contributing

1. Create a feature branch and describe the intended behavior.
2. Do not commit `.env`, credentials, signing keystores, APKs containing secrets, database dumps or customer telemetry.
3. Run the backend health/API checks and validate the dashboard in a browser.
4. For Android changes, build and test on an emulator and target hardware where possible.
5. Update `docs/PRD.md`, `docs/TECHNICAL_DESIGN.md` and the release checklist when behavior or deployment changes.
6. Submit a pull request with test evidence and rollback notes.
